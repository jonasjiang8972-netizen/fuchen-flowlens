# 拂尘 FlowLens — 数据流图谱与攻击路径 (v0.8.0)

> 两张由真实流量驱动的关系图：**调用链路**（数据流图谱）与**攻击路径**。前端用 D3 力导向布局渲染。

## 一、调用链路（`GET /api/v1/graph/flow`）

每处理一条事件，平台把它归约成一次观测，聚合成四层图：

```
调用方(源 IP) ──▶ 服务(host / service_name) ──▶ 接口(方法+归一化路径) ──▶ 敏感字段
   layer 0            layer 1                       layer 2                   layer 3
```

- 连线累计调用数、失败数（状态码 ≥ 400）、响应字节数。
- 调用方按地址分为**内网**（私有/回环/链路本地）和**外网**。
- 风险标记：接口暴露敏感字段 → `high`；某节点调用 ≥ 20 次且失败率 ≥ 50%（探测、撞库特征）→ `medium`。
- 三种视图：`business`（全部）、`service`（服务与接口）、`data`（只保留暴露敏感字段的接口）。
- `q` 按节点名称过滤；`limit` 取调用量最高的前 N 条连线（默认 150，上限 500），截断时 `stats.truncated=true`。

## 二、攻击路径（`GET /api/v1/graph/attack`）

以**来源地址**为单位，把它触发的告警按时间串成攻击链，并叠加平台记录到的该来源行为：

```
攻击来源 ──▶ 账号 ──▶ 访问过的接口 ──▶ 暴露的敏感字段
    └────▶ 告警 ──(后续)──▶ 告警 ──(后续)──▶ …
```

告警按检测项映射到攻击阶段：

| 阶段 | 序 | 检测项 |
|---|---|---|
| 侦察探测 | 1 | FR-RISK-002 爬虫/自动化 |
| 凭据攻击 | 2 | FR-DET-002 撞库、FR-RISK-003 |
| 对象枚举 | 3 | FR-DET-001 BOLA |
| 权限提升 | 4 | FR-DET-005 BFLA |
| 数据外泄 | 5 | FR-DLP-001 / 003 敏感数据 |
| 异常访问 | 0 | 其他（不参与升级判断） |

`escalating=true` 表示后续告警的阶段序号高于前序（例如先撞库、后数据外泄）。

- `alert_id` 聚焦某条告警所属的来源，返回该来源的全部告警。
- 默认最多 10 个来源，按最高严重度、风险分排序。已关闭的告警不计入。
- 每个来源最多画 8 个接口，优先展示暴露敏感字段或出现失败的接口。

## 三、容量与生命周期

| 项 | 上限 / 行为 |
|---|---|
| 节点 / 连线 | 5000 / 20000，超出的观测不记录，计入 `stats.dropped`，前端会提示 |
| 活跃来源 | 5000；每个来源最多记录 200 个接口 |
| 保留期 | 7 天未出现的连线、节点、来源每 10 分钟清理一次 |
| 持久化 | **不持久化**。重启后由新流量重建；PostgreSQL 中的告警不受影响 |

## 四、演示数据

`--demo` 或 `FLOWLENS_SEED_DEMO=true` 时，若图谱为空，会写入与示例告警一致的样例流量（撞库后接管账号、账号遍历订单、支付撞卡等）。图谱已有真实流量时**不会**写入。静态演示站（`VITE_DEMO=true`）使用前端内置样例。

## 五、已知限制

- 攻击路径只按**来源地址**归并；同一攻击者更换地址后会显示为多个来源。设备指纹关联留待后续版本。
- 告警本身不记录被攻击的接口，接口信息来自图谱记录的来源行为，因此重启后、或活动已超出保留期的旧告警只显示告警节点。
- 单机内存图谱；多副本部署时每个副本只看到自己接收的流量。
