# 拂尘 FlowLens — 合规报告 (v1.0.0)

> 用平台当前的真实状态，逐项对照等保三级和金融行业要求自查。做不到的、判断不了的如实标出，不会凑成“符合”。

**这不是等保测评结论。** 它是产品对自身运行状态的自查，帮助你在正式测评前发现差距；结论只能由具备资质的测评机构出具。

## 一、每一项是怎么判定的

每个检查项都标明判定方式：

| 判定方式 | 含义 | 例子 |
|---|---|---|
| **实时** | 由平台当前的配置和数据算出 | 口令策略是否达标、还有几个账号没改初始口令、审计哈希链是否完好、有多少影子接口 |
| **能力** | 说明产品有没有实现该功能，取自代码，未经现场验证 | 双因素认证（未实现）、SM2/SM4（未实现）、采集端脱敏（已实现） |
| **需人工** | 软件无法判断 | 机房、管理制度、备份恢复演练、渗透测试、密评 |

结论有四种：**符合 / 部分符合 / 不符合 / 需人工核查**。

几条不会被凑成“符合”的规则：

- 平台**没有实现**的功能（双因素、SIEM 对接、数据分级、SM2/SM4）无论怎么配置都不会符合。
- **无法验证**的事（数据库连接串里没有 sslmode、审计完整性校验没跑成功、还没发现任何资产）标“需人工核查”，不算通过。
- 前置代理终止的 TLS 平台看不到证书，只能算“部分符合”。
- 没有配置数据库时，审计日志只在内存里，“持久化”一项不符合。

## 二、模板

| 模板 | 用途 |
|---|---|
| `mlps3` 等保 2.0 三级自查 | 对照 GB/T 22239-2019 第三级：安全通信网络、安全计算环境、安全管理中心 |
| `finance` 金融行业自查 | 在上面基础上加入数据分级（JR/T 0197、JR/T 0223）、界面脱敏与明文调阅（JR/T 0171），条目引用 JR/T 0071、JR/T 0171 和相关法律 |

条款编号只到“节”一级（例如 8.1.4.1 身份鉴别），用于定位。**请以标准原文为准**；口令长度、更换周期等数值以客户内部制度为准。

## 三、检查项

| 分类 | 检查项 | 判定 |
|---|---|---|
| 身份鉴别 | 口令复杂度/有效期/历史；登录失败锁定；会话超时；初始口令已修改；长期未登录账号 | 实时 |
| | 双因素认证 | 能力（**未实现，不符合**） |
| 访问控制与三权分立 | 系统/审计/安全三类管理员都有启用账号 | 实时 |
| | 最小权限与逐接口授权 | 能力 |
| 安全审计 | 日志留存 ≥ 180 天；持久化；SM3 哈希链完整性校验（生成报告时实际校验一次） | 实时 |
| | 关键操作可追溯到人 | 能力 |
| | 对接 SOC/SIEM | 能力（**未实现，不符合**） |
| 通信传输与密码应用 | 控制台/API 传输加密；采集器通道认证；数据库连接加密 | 实时 |
| | 商用密码 SM2/SM3/SM4 | 能力（**部分**：只用了 SM3） |
| 数据安全与个人信息保护 | 接口返回的敏感数据已脱敏；敏感数据接口有责任人 | 实时 |
| | 采集端脱敏 | 能力 |
| | 数据分级与全生命周期（仅金融模板）；界面明文授权调阅（仅金融模板） | 能力（**未实现 / 部分**） |
| API 资产与采集覆盖 | 影子/僵尸接口占比；责任人覆盖；采集器在线率 | 实时 |
| 入侵防范与处置响应 | 检测规则启用；告警及时处置（工单 SLA）；处置闭环与复核；联动处置能力；异常行为检测（BOLA 模型） | 实时 |
| 管理制度与人工核查 | 机房；管理制度与人员；备份与恢复演练；漏洞扫描与渗透测试；密评 | 需人工 |

阈值：影子+僵尸接口占比 ≤10% 为部分符合，超过为不符合；未认领接口占比 ≤20% 为部分符合，超过为不符合；采集器 ≥90% 在线为部分符合；检测规则启用 ≥50% 为部分符合。

## 四、谁能看

报告汇总了整个平台的安全状况，所以由单独的权限 `report.read` 控制，**只有安全管理员**有。只读用户、分析员、系统管理员、审计管理员都不能生成或导出。

报告里**不出现账号名**。这些内容由系统管理员在管理后台处理，安全控制台不应因为生成报告而看到账号清单，报告只给计数。

生成报告和导出文件都会写入审计日志（`report.generate`、`report.export`，含导出格式和操作人）。

## 五、API

| 接口 | 说明 |
|---|---|
| `GET /reports/compliance/templates` | 模板列表 |
| `GET /reports/compliance?template=mlps3\|finance` | 生成报告（JSON） |
| `GET /reports/compliance/export?template=&format=html\|csv` | 下载。HTML 是自包含、可打印的页面；CSV 带 BOM，Excel 可直接打开，以 `= + - @` 开头的单元格会被中和，避免被当作公式执行 |

生成报告时会实际运行一次审计哈希链的增量校验，耗时取决于上次校验以来新增的记录数。

## 六、已知限制

- 这份自查只覆盖**软件产品自身**能判断的部分。等保测评的对象是整个信息系统，包括物理环境、网络架构、制度和人员，这些在“需人工”里列出。
- “能力”项的结论取自代码的实现状态，不是现场验证；随着功能变化需要同步更新 `platform/internal/compliance/compliance.go`。
- 阈值（如 10%、20%、90%）是经验值，不是标准规定。
- 不做趋势对比和历史留档；每次都是当前状态的快照。
- 没有 PDF 导出：HTML 页面可以直接用浏览器打印为 PDF。
